Privacy Policy

Effective date: September 18, 2026

PublishHarbor is a local-first desktop application for preparing, scheduling and publishing a user's own social-media content. This policy explains what information the application may process and why.

1. Information stored locally

PublishHarbor stores workspace information on the user's computer, including projects, media file paths, account labels, post drafts, scheduling information, publication job state and locally cached analytics data. This local workspace is not uploaded to a PublishHarbor cloud account by default.

2. Connected social accounts

When a user connects a supported social platform, PublishHarbor uses that platform's authorization flow to obtain the permissions required for the features the user chooses to use. Depending on the provider, PublishHarbor may process identifiers such as an account or channel ID, display name, granted scopes, access tokens, refresh tokens, publication IDs and provider-returned URLs.

Supported credentials and tokens are stored using operating-system credential storage where implemented. PublishHarbor does not intentionally place provider secrets in the public website or public source repositories.

3. Content sent to providers

When the user chooses to publish, schedule or retrieve analytics, PublishHarbor sends the information necessary to the selected provider. This may include the selected video file, title or caption, publishing settings, privacy choices and account identifier. The provider's own privacy policy and terms apply to information processed by that provider.

4. Optional technical services

Some features may use optional external or user-configured services. For example, an Instagram publishing workflow may temporarily use a media delivery bridge so that Meta can retrieve a local video file during publishing. Remote-control or other optional integrations may also communicate with a configured service. Such features are used only when configured or invoked and may process the minimum technical information required to perform that function.

5. Analytics

If the user requests analytics, PublishHarbor may retrieve performance data from connected platforms and cache that information locally. Examples include views, likes, comments, shares and media-level identifiers. PublishHarbor does not sell this analytics data.

6. Data selling and advertising

PublishHarbor does not sell personal data. PublishHarbor does not operate an advertising network and does not use connected-account data to build advertising profiles.

7. Data retention and deletion

Local workspace data remains on the user's device until the user removes it, resets the local application data, or deletes the relevant files. Disconnecting a social account removes locally stored authorization for that account where supported. A social platform may retain information according to its own policies.

8. Security

PublishHarbor is designed to minimize unnecessary data movement and to isolate authorizations by account. No software can guarantee absolute security, but the project aims to use scoped OAuth permissions, operating-system credential storage and explicit publishing actions.

9. Children

PublishHarbor is not directed to children and is intended for users who are legally able to connect and operate the social-media accounts they choose to use.

10. Changes to this policy

This policy may be updated as PublishHarbor gains new integrations or distribution methods. The effective date at the top of this page will be updated when material changes are made.

11. Contact

Questions about this policy can be submitted through the public project contact page: GitHub Issues.
